UE5 移动端全 OnePass 渲染管线

概述

在 UE5 移动端渲染管线中实现全 OnePass：主视图的全部光栅阶段（Base/GBuffer → Decals → Lighting → Fog → Translucency → Tonemap）在一次物理 Vulkan RenderPass 内完成，主 SceneColor/GBuffer 全程保持在 GPU tile memory（Memoryless），永不 Store/Reload。

  • 适用平台: Android Vulkan（Metal/GLES 保持现有 SinglePass 路径）
  • 预期收益: 省掉 2~4 次 SceneColor/GBuffer 的 Store/Reload 带宽；TBDR GPU（Adreno/Mali）收益最大
  • 核心机制: 新增 ESubpassHint 复合拓扑 —— Forward 5-subpass / Deferred 6-subpass
  • 改动范围: 16 个文件，+341/-138 行（Win64 构建验证通过，真机待验证）

如何开启

前置条件（启动前配置）

启用判定（全部满足才生效，否则自动回退并输出一次性 warning）

  • r.Mobile.OnePass=1
  • Vulkan 平台（Android）
  • 设备支持 inline tonemap resolve（bTonemapSubpassInline）
  • 设备 maxColorAttachments >= 5（基础 Deferred：SceneColor + GBufferA/B/C + FinalOutput）
  • 非 MultiPass 路径（!bRequiresMultiPass，即平台支持 FramebufferFetch/SubPass）

改动清单

RHI 层 — 新增 ESubpassHint 复合拓扑

原引擎 ESubpassHint 只支持固定模板：DepthReadSubpass=2 个、DeferredShadingSubpass=3 个、CustomResolveSubpass=3 个 subpass，无法容纳独立 Fog/Translucency/Tonemap subpass。

# 文件 改动
1 RHI/Public/RHIResources.h 新增 ForwardFullOnePassSubpass / DeferredFullOnePassSubpass 枚举
2 VulkanRHI/Private/VulkanRenderpass.h Builder 支持 5/6-subpass 拓扑；subpass 依赖链动态索引；CustomResolve 输出改为 last-attachment（原硬编码 attachment 1，Deferred 下会写错到 GBufferA）
3 VulkanRHI/Private/VulkanRenderTargetLayout.cpp 新 hint 的最后 color attachment 识别为单采样 final target（RenderPassInfo 与 PSO 两条路径）
4 VulkanRHI/Private/VulkanPipeline.cpp 各 subpass 的 RT 数量（SP≥1/≥2 只写 SceneColor）与 resolve subpass 强制 RasterizationSamples=1
5 VulkanRHI/Private/VulkanRenderTarget.cpp 新 hint 强制 classic RenderPass（KHR_dynamic_rendering_local_read 未实现，走 dynamic rendering 会破坏 subpass 语义）
6 VulkanRHI/Private/VulkanContext.cpp attachment NumSamples 校验覆盖新 hint
7 RHI/Private/RHI.cpp ValidateRenderPassInfo 的 depth input-attachment 校验覆盖新 hint

渲染器层 — 全 OnePass 渲染路径 + PSO 预缓存一致性

# 文件 改动
8 MobileShadingRenderer.cpp 新增 RenderForwardFullOnePass（4 次 NextSubpass）与 RenderDeferredFullOnePass（5 次 NextSubpass，追加 ViewFamilyTexture 为最后 attachment）；新增 bFullOnePass 判定；dispatch 三分支
9 SceneRendering.h bFullOnePass 成员 + 两个新函数声明
10 Engine/Private/SceneUtils.cpp IsMobileTonemapSubpassEnabled：r.Mobile.OnePass 开启时允许 Deferred 使用 inline tonemap subpass（原代码硬排除 Deferred）
11 MeshPassProcessor.cpp GetSubpassHint() 镜像 bFullOnePass 判定，保证 PSO 预缓存 hint 与运行时 render pass 一致
12 MobileBasePass.cpp Translucency subpass index 映射：ForwardFullOnePass=3、DeferredFullOnePass=4（原 Deferred=2/Forward=1）
13 MobileDeferredShadingPass.cpp Deferred Lighting PSO hint：OnePass 开启时用 DeferredFullOnePassSubpass（subpass index 仍为 2）

平台兼容性

平台 全 OnePass 说明
Android Vulkan ✅（新 5/6-subpass 拓扑） 需 maxColorAttachments>=5、AllowFramebufferFetch=1
Android GLES ❌ 保持现有 SinglePass/MultiPass PLS 限 128-bit GBuffer；non-coherent fetch 需 barrier
iOS Metal ❌ 保持现有 framebuffer fetch encoder Metal 无真实 subpass；inline tonemap 仅 Vulkan
Desktop PC ❌ 无效果 MobileAllowFramebufferFetch 返回 false

已知问题 & 注意事项

  1. 真机验证未完成：subpass 拓扑/依赖链只通过编译器验证，需 RenderDoc + validation layer 真机确认（当前代码 0 GPU 执行记录）。
  2. Deferred shadowed point light：仍走 MultiPass 的 per-light mask 流程（SinglePass 路径本就不支持，非新增回归）。
  3. Dynamic Rendering：新 hint 强制 classic RenderPass；KHR_dynamic_rendering_local_read 实现后才能解锁。
  4. 功能降级（与现有 Forward inline-tonemap 路径一致）：Distortion / SceneColorCopy 折射材质 / SingleLayerWater 折射不采样主 SceneColor；FXAA 用 MSAA 替代；PostOpaque Extensions 不调用。
  5. PSO 一致性：GetSubpassHint()（预缓存）与 bFullOnePass（运行时）使用同一组条件（CVar + Vulkan + inline tonemap 可用），由构造保证一致。
